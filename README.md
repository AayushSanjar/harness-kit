# harness-kit

A reusable Claude Code harness, packaged as a plugin and served from this repository as its own marketplace.
The plugin lives in `plugins/harness-kit/`; `tests/validate.sh` checks it and runs in CI.
A release is made by the person, on the branch, with `plugins/harness-kit/scripts/release.sh v<version>`: it runs the check, pushes the branch, waits for CI, then fast-forwards `main` and pushes it with the tag. When gh cannot read the CI result (after 3 tries, 10 seconds apart), it stops with "CI result unknown" and pushes nothing to `main`.
CI runs the fault replays (`plugins/harness-kit/scripts/replay-faults.sh`, every entry of `.harness/mutations.tsv`) on each push to main, as one baseline job and 8 shard jobs side by side, judged together; to run them on a branch: `gh workflow run validate.yml --ref <branch>`.
Every long-running step the harness starts runs under a hard time limit, through one helper, `plugins/harness-kit/scripts/time-limit.mjs`: the check (540 s), a reviewer run (900 s), a wait on one CI run (900 s), a gh read (60 s), a git push, fetch or ls-remote (300 s, and without prompts), and upgrade.sh's plugin commands and headless session (120 s each). Past its limit, a step's whole process group is stopped (SIGTERM, then SIGKILL 10 s later) and reported as TIMEOUT; each limit can be overridden by its environment variable, listed in the helper's header. The Stop hook stops its check at 540 s, before its own 600-second limit, so it blocks rather than lets Claude stop unchecked. Temporary files and worktrees are cleaned up on any exit, and what a forced kill leaves is swept the next time the helper starts, from a registry that is this user's alone (`$TMPDIR/harness-kit-live`, or the folder `HARNESS_KIT_REGISTRY_DIR` names; a fault replay gives each run its own), and only when the process that owned it is surely gone. `plugins/harness-kit/scripts/check-limits.mjs`, run by `tests/validate.sh`, fails when a script starts long work without the helper, and a PreToolUse hook refuses any background Bash command not wrapped in it.
The Stop hook skips its check when nothing has changed since the check last passed, less than 24 hours ago: the working tree (tracked files, and untracked files git does not ignore), HEAD and the refs, the check command, the plugin version, Node's version and the check limit must all match its last pass, recorded in `<git dir>/harness-kit/stop-gate-pass`, which only the hook writes; any change, or anything it cannot read, runs the full check.
The Stop hook's check, each fault replay, and each ship.sh and release.sh run (and release.sh's check) record their time as a TIMED line in the local event log, `.git/harness-kit/events.tsv`, and say once a session when one is over its budget: the check 120 s, a replay 180 s, ship.sh and release.sh 600 s each, overridden by `HARNESS_KIT_BUDGET_CHECK_SECONDS`, `HARNESS_KIT_BUDGET_REPLAY_SECONDS`, `HARNESS_KIT_BUDGET_SHIP_SECONDS` and `HARNESS_KIT_BUDGET_RELEASE_SECONDS`.
Each session starts with the days since this clone's last full fault replay, and from 7 days on (or with none) the command that runs one; CI's replays are not counted.
Background research is in `research/`.
